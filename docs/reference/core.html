Loading a list ​

injectResourceList<T>(resourceName: string \| (() => string), params?: () => ListParams \| undefined): ResourceRef<ListResult<T> \| undefined> wraps DataProvider.getList in Angular's native resource() API, returning a ResourceRef with the following members (documented under ResourceRef in @angular/core):

MemberTypeWhat it holds
valueSignal<ListResult<T> | undefined>The loaded result. undefined while loading, populated when done, kept across status changes.
statusSignal<ResourceStatus>'loading', 'reloading', 'error', or 'success'.
errorSignal<Error | undefined>The error if status is 'error'.
isLoadingSignal<boolean>Shortcut for loading/reloading.
reload()() => voidTriggers a new load.

Two notes:

  • The resource name may be a function (e.g. a route parameter signal); changing the return value reloads automatically.
  • When params returns undefined, loading is skipped entirely per resource()'s own convention.

Source: libs/core/src/lib/resource-list.ts lines 11–28.

Field types ​

type FieldType = 'text' | 'number' | 'boolean' | 'date' | 'timestamp' | 'time' | 'numeric'

TypeInputKept as
text<input type="text">String (always)
number<input type="number">Number (always)
boolean<mat-checkbox> / checkboxBoolean (always)
date<input type="text"> pattern YYYY-MM-DDString (never Date)
timestamp<input type="text"> pattern ISO datetimeString (never Date)
time<input type="text"> pattern HH:mm:ssString (never Date)
numeric<input type="text"> pattern decimal digitsString (never Number)

date, timestamp, time and numeric remain strings end to end so a calendar date, a zoned time, or a bigint/high-precision numeric round-trips without rounding through JSON.parse or Date. Validation uses regex patterns defined in libs/core/src/lib/field-presentation.ts lines 15–25.

Source: libs/core/src/lib/field-presentation.ts lines 3–48 (INPUT_TYPE_BY_FIELD_TYPE, FORMAT_PATTERN_BY_FIELD_TYPE, TEXT_INPUT_BOUND_FIELD_TYPES).

Five helpers turn a Field into what a form renders; both UI layers call them instead of keeping their own copy. inputTypeForField(field): string returns the INPUT_TYPE_BY_FIELD_TYPE lookup. formatPatternForField(field): RegExp | undefined returns the validation pattern for the type, undefined where there is none. formatHintForField(field): string returns the hint shown under the input. fieldRequiresValueWhenEmpty(field): boolean is true for date, timestamp, time and numeric when the field is not nullable. isTextInputBoundField(field): boolean is true when the type binds a plain text input. Source: same file, lines 50–70.

List params ​

interface ListParams:

PropertyTypeWhat it does
pagination?.currentnumberPage number (1-based).
pagination?.pageSizenumberRows per page.
sorters?{ field: string; order: 'asc' | 'desc' }[]Sort fields and direction.
filters?readonly Filter[] | Record<string, FilterValue | null | undefined>AND-combined filters; shorthand object syntax maps values to eq. Values are normalized (libs/core/src/lib/normalize-filters.ts) and unsupported operators are rejected (libs/core/src/lib/reject-unsupported-filters.ts). Anything else is rejected before a request is sent.

Three helpers apply those rules before any request. normalizeFilters(filters: ListParams['filters']): Filter[] returns [] for undefined or null, copies an array, turns the shorthand record into { field, operator: 'eq', value } members (a null value becomes the null operator), and throws on a single filter object or a value that is not a plain object. rejectUnsupportedFilters(filters, supported) throws Unsupported filter operator "<operator>" on field "<field>" for an operator the backend cannot express. validateListParams(params) rejects a malformed page number, sorter or filter. Sources: libs/core/src/lib/normalize-filters.ts line 16, libs/core/src/lib/reject-unsupported-filters.ts lines 4–7, libs/core/src/lib/validate-list-params.ts line 83.

Tokens and identity ​

Three InjectionTokens are provided by @pidrang/core:

TokenTypeRequiredDescription
DATA_PROVIDERInjectionToken<DataProvider>YesRegistered via providePidrang({ dataProvider }). Injected by injectDataProvider(). Source: libs/core/src/lib/tokens.ts line 7.
RESOURCESInjectionToken<Resource[]>YesRegistered via providePidrang({ resources }). Injected by injectResources() / injectResource(). Source: same file, line 9.
AUTH_PROVIDERInjectionToken<AuthProvider>NoOptional — only registered when authProvider is passed to providePidrang(). Injected with { optional: true }. Source: same file, line 11.

When authProvider is configured, SESSION_IDENTITY is also provided: a WritableSignal<AuthIdentity | null> created by watchIdentity. It starts at null, refreshes once at startup and again on every onSessionChange notification, and keeps its last value when getIdentity() rejects. It is not the same signal as injectAuthSession().value(), which starts at undefined and becomes undefined on error. Source: libs/core/src/lib/provide-pidrang.ts lines 23-45 (watchIdentity), libs/core/src/lib/session-identity.ts, libs/core/src/lib/auth-session.ts lines 16-51.
