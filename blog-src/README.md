# Blog source

`blog-src/` holds the Hugo configuration, the layouts, the sync script and the fixtures of the blog at `https://pidrang.dev/blog/`. The posts are not written here: they are discussions of the Blog category of [pidrang/pidrang](https://github.com/pidrang/pidrang). `blog/` at the root is generated by `sync.mjs` and is never edited by hand.

## Write a post

1. In `pidrang/pidrang`, open a discussion in the **Blog** category. Its title is the post title and its body is the post in GitHub Markdown.
2. Start the body with a metadata block. GitHub does not render it:

   ```markdown
   <!--
   slug: signal-first-crud
   description: One list page for every table with Angular 22 resource() and a typed Resource.
   cover: /assets/blog/signal-first-crud.png
   cover_alt: Generated list page of the users table
   -->
   ```

   | Key | Required | Rule |
   | --- | --- | --- |
   | `slug` | yes | `^[a-z0-9]+(-[a-z0-9]+)*$`, unique across posts |
   | `description` | yes | 1 to 160 characters, one line |
   | `cover` | no | Path starting with `/assets/blog/`, no `..`; the file must exist in this repository |
   | `cover_alt` | if `cover` | 1 to 200 characters |

3. Add exactly one label `blog: <category>`, with `<category>` one of `tutorials`, `architecture`, `releases`, `community`, `ecosystem`. Other labels are ignored; an unknown `blog: ` label is an error.
4. Put images in `assets/blog/` of this repository and reference them with absolute paths (`/assets/blog/x.png`). Images pasted into the discussion editor (`user-attachments`) are refused.
5. The body must not contain `<script`.

Dates come from the discussion: `date` is its creation time and `lastmod` its last update.

Unpublish a post by deleting its discussion or moving it out of the Blog category. The next sync removes it.

Every run of the sync rereads the whole Blog category. An invalid post makes the run fail with the discussion number and URL, and nothing is written.

## Build locally

Use a fork with Discussions enabled and a Blog category to test; never create test discussions in `pidrang/pidrang`, since they are public at once.

1. Install Hugo 0.168.0 (standard edition) outside the repositories:

   ```sh
   mkdir -p /tmp/hugo-0.168.0 && cd /tmp/hugo-0.168.0
   gh release download v0.168.0 -R gohugoio/hugo -p 'hugo_0.168.0_linux-amd64.tar.gz' -p 'hugo_0.168.0_checksums.txt'
   sha256sum -c --ignore-missing hugo_0.168.0_checksums.txt
   tar -xzf hugo_0.168.0_linux-amd64.tar.gz hugo
   ```

2. From the root of the site repository, build the fixtures:

   ```sh
   HUGO_BIN=/tmp/hugo-0.168.0/hugo node blog-src/sync.mjs --fixtures blog-src/fixtures/discussions.json
   ```

3. Serve the site and open `http://localhost:8000/blog/`:

   ```sh
   python3 -m http.server 8000
   ```

4. Remove the generated output when done: `rm -rf blog`. Only the sync workflow publishes `blog/`.

## Tests

From the root of the site repository:

```sh
node --test blog-src/sync.test.mjs
HUGO_BIN=/tmp/hugo-0.168.0/hugo node --test blog-src/sync.test.mjs blog-src/sync.integration.test.mjs
```

The unit tests need no Hugo. The integration test runs the real Hugo build on the fixtures; it is skipped without `HUGO_BIN` and restores the existing `blog/` when it ends.

## Layouts

Every page copies the `<head>` pattern, the header and the footer of the other pages. When the site header changes, update `layouts/partials/header.html` in the same change. giscus loads only on post pages, with `data-mapping="number"` on the post's own discussion. Post styles live in `styles.css` under `.post-body`.
